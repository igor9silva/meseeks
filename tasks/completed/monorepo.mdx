# Reorganize repository into Bun monorepo

The CI/tooling drift is a repository-structure problem, not just a script problem. Root-level commands currently traverse mixed projects with different constraints (main app, organizer, proof-of-concepts), which forces brittle exclusions and creates noisy failures.

The durable fix is to make workspace boundaries explicit through a proper monorepo layout with `apps/` for runnable apps and `packages/` for libraries, experiments, and placeholders.

Bun is the preferred workspace/package manager for this migration. Use pnpm only if we hit a documented blocking issue.

Note: we have a private/ dir which is a completely separate repo (because it should remaing private). However, it does interact with the main repo constantly (For example, it has a task structure that follows the same pattern as the parent repo, and they are all handled by the same scripts and also configs.). Ideally it should sit as a package in the monorepo, but it MUST REMAIN PRIVATE. The only cost of this approach is that Worktrees or Cloud Tasks on Codex might not be able to see private stuff. But this is okay; I'm willing to pay for that and only work on private stuff in local mode.

## Objective

Reorganize this repository into a Bun-first monorepo where each package has explicit ownership and scripts. The main Meseeks app remains the only deployment gate through Vercel's Git integration; no GitHub Actions are introduced.
