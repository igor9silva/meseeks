# Build Agent Regression Test Harness

Meseeks does not yet have a dedicated system for regression tests that exercise agent behavior across tool responses, conversation state, and final assistant-visible output. That makes it too easy for prompt/tool fixes to regress silently.

A concrete failure exposed the gap: `twitter_search` can return at most 20 results per page and may include a `continuation_token` when more results exist. A prior task claimed it had compiled every tweet from a date range even though broad `twitter_search` calls hit the 20-result page limit and still had continuation tokens.

The immediate tool schema now exposes `continuation_token`, but the real fix is a reusable regression harness that can encode this and future agent-behavior failures as deterministic tests.

## Objective
Design and implement a lightweight local regression test system for Meseeks agent behavior, starting with the Twitter pagination failure as the first fixture.

Acceptance criteria:

- The repo has a documented command for running agent regression tests locally.
- The harness can run deterministic fixtures without calling live external APIs or mutating Convex data.
- Fixtures can model tool responses, follow-up tool availability, and final assistant-visible `say()` output.
- The first fixture covers a `twitter_search` response with 20 results and a non-empty `continuation_token`.
- The Twitter fixture asserts that the agent either paginates with the same query and filters using that token, or explicitly marks the result as partial.
- The Twitter fixture asserts that final assistant-visible output must not claim "all", "every", "complete", or equivalent exhaustive wording while an unconsumed continuation token exists.
- The harness output is concise enough to be useful in normal development and CI-style checks.

## Subtasks
- [ ] Choose the narrowest reusable boundary for agent regressions, such as action execution fixtures, skill/tool response fixtures, or rendered conversation-history fixtures.
- [ ] Define a fixture format for user instructions, available skills, mocked tool responses, expected follow-up actions, and forbidden/required final wording.
- [ ] Add the capped Twitter-search fixture and assertion for unconsumed `continuation_token`.
- [ ] Add a local command to run the regression harness and document it near the implementation.
- [ ] Verify the Twitter regression fails without the behavior/schema fix and passes after the fix.
- [ ] Add one short guide for future regressions so bug investigations can turn into fixtures instead of one-off prompt edits.
