# Billing and lifecycle

Known behavior gaps are explicit in production paths and in security findings:
- `lib/polar.ts`
  - uses fixed `durationMonths: 1` instead of webhook period end
  - `order.refunded` path is not implemented
  - subscription renewal can re-credit on duplicate delivery
  - canceled subscription status transition is deferred/commented
- `convex/action/lifecycle.ts`
  - interruption costs are not tracked when action result is ignored
- `convex/action/lifecycle.private.ts`
  - reactions are not persisted in details payload
  - `maxTokens` DB naming mismatch is pending rename cleanup
- `convex/subscriptions/private.ts` and `convex/topUps/private.ts`
  - billing state updates need replay-safe/idempotent guards

These are correctness and reliability issues, not cosmetic TODOs.

## Objective
Make billing and lifecycle paths explicit, idempotent, reversible, auditable, and regression-tested for edge cases.

## Subtasks
- [ ] Harden webhook-to-billing mapping:
  - derive subscription validity from webhook timestamps/period end (not fixed month constants)
  - implement `order.refunded` handling with deterministic credit reversal
  - ensure renewal credits cannot be applied more than once per billing cycle
  - implement cancellation transition scheduling/state update flow
- [ ] Enforce lifecycle persistence invariants in action pipeline:
  - persist resolved reactions in action details (`convex/action/lifecycle.private.ts`)
  - record interruption-cost metadata when result is discarded due to skip/stop
  - complete DB naming cleanup for token/max-output fields and migrate readers
- [ ] Add deterministic idempotency and replay guards:
  - ensure duplicate webhook delivery does not double-credit or double-revoke
  - key idempotency by webhook event ID and payment/subscription lifecycle state
  - persist processed-event markers
  - validate action resolve path is single-write and replay-safe
- [ ] Add regression tests for critical scenarios:
  - webhook fixtures: `order.paid`, `order.refunded`, `subscription.revoked`, cancellation flow, duplicate delivery
  - lifecycle fixtures: timeout, manual stop, pending-authorization, multi-reaction resolve
- [ ] Add operational checks:
  - add audit logs for activate, renew, refund, and revoke flows
  - logging should keep Sentry severity semantics already in use (`info`/`warn`/`error`) while avoiding false urgent noise
