# Upgrade app schemas to native Zod 4 and remove Zodex

The current schema stack is split across `zod/v3`, `convex-helpers/server/zod3`, `better-auth` on Zod 4, and `zodex` for schema serialization. That split already caused SSR/runtime breakage in production, including Nitro resolving a Zod 4 runtime while parts of the app still composed Zod 3 schemas.

One possible interim mitigation is to keep importing `zod/v3` while moving `package.json` to Zod 4. That was tested, but it is still a compatibility shim and did not hold cleanly across this repo's package boundaries.

## Objective
Move the repo to a coherent Zod 4 stack, remove `zodex`, and replace stored schema serialization with a format that works with the AI SDK and survives SSR/runtime bundling without mixed-major failures.

The exact serializer decision is still open:
- replace `zodex` with native Zod 4 to/from JSON Schema helpers
- or upgrade `zodex` itself if a Zod 4-compatible path exists and is good enough

## Subtasks
- [ ] Audit all imports of `zod/v3`, `convex-helpers/server/zod3`, and `zodex` across `convex/`, `schemas/`, `src/`, `lib/`, and `skills/`.
- [ ] Replace Convex helper imports with `convex-helpers/server/zod4` where supported, and move app-owned schemas to Zod 4 definitions.
- [ ] Decide whether to replace `zodex` with native Zod 4 to/from JSON Schema helpers or upgrade `zodex` itself, then implement that choice in `lib/zodToString.ts` and the `skills.inputSchema` flow.
- [ ] Add backward-compatible reads for legacy `skills.inputSchema` values already stored in Convex so old skills do not break immediately after deploy.
- [ ] Add and validate a one-off migration that rewrites persisted legacy `skills.inputSchema` strings to the new JSON Schema format.
- [ ] Remove `zodex` and any remaining Zod 3-only compatibility code once reads, writes, build, and migrations are green.
