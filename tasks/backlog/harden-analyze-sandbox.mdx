# Harden Analyze Sandbox Contract

`analyze()` currently treats Daytona's response as plain text. That hides the execution contract: Python exceptions can come back as `HTTP 200`, tracebacks include base64 wrapper noise, and the next loop often sees output without the code that produced it. The result is a messy auto-fix path: broken code can look like a successful action, and debugging depends on UI/debug state instead of durable action details.

## Objective
Make `analyze()` debuggable and contract-driven: failed code fails the action, execution details preserve the useful request/response data, and Daytona returns a structured result without traceback wrapper junk.

## Subtasks
- [ ] Expose `analyze()` code to the next model turn when useful, especially on traceback/failure paths; keep truncation explicit so large code does not blow up history.
- [ ] Make broken Python fail the action instead of succeeding with traceback text; preserve stdout/stderr/error details so auto-fix has enough evidence.
- [ ] Store hard-skill request bodies in action details with a redaction/truncation policy; request headers stay redacted, and `analyze()` code should be inspectable.
- [ ] Change Daytona proxy responses to structured JSON: `ok`, `exitCode`, `stdout`, `stderr`, and typed error fields.
- [ ] Return an HTTP 4XX status from Daytona for user-code execution failures, likely `422`, while keeping infra/proxy failures as `5XX`.
- [ ] Remove Daytona proxy traceback noise by compiling decoded code with a useful filename such as `analyze.py` instead of surfacing the base64 `exec(...)` wrapper.

## Acceptance Criteria
- A Python `raise Exception("probe")` through `analyze()` records the action as failed and stores structured stdout/stderr/error details.
- A successful `print("probe")` run still records the action as succeeded with stdout visible as the result.
- The next model turn can see the failed `analyze()` code or a clearly truncated version of it, not only the traceback.
- Debug action details include sanitized/truncated request body data for hard skills, with no persisted secret headers.
- Daytona returns structured JSON for both success and failure, and user-code failures no longer use `HTTP 200`.
- Tracebacks point at user code filenames/line numbers, not the proxy's base64 wrapper.
