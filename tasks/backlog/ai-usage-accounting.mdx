# Persist normalized AI SDK usage and charge reasoning tokens correctly

## Context
Meseeks now uses an AI SDK version that exposes normalized language model usage, including cached input and reasoning output details. Earlier versions did not expose this reliably, so the current action detail and billing paths only persist coarse input/output totals.

DEV testing of xAI Grok models showed `usage.outputTokenDetails.reasoningTokens` in Convex logs. xAI dashboard logs are not currently useful, so Meseeks must persist enough provider usage data to audit cost locally.

The important billing constraint: AI SDK `usage.outputTokens` is total output tokens. For xAI Responses, that total already includes reasoning tokens, with the split exposed under `usage.outputTokenDetails`. Do not charge `output.total` and `output.reasoning` on top of each other.

## Objective
Make AI model usage persistence and provider-cost calculation use AI SDK normalized usage as the canonical source of truth across providers, including reasoning tokens, cached input tokens, raw audit data, and clear cost line items.

## Subtasks
- [ ] Extend `schemas/actionDetailSchema.tsx` to persist normalized language model usage: input total/uncached/cache read/cache write, output total/text/reasoning/other, total tokens, and raw provider usage.
- [ ] Update `skills/createAITool.ts` to normalize `LanguageModelUsage` once and persist the normalized shape in action details.
- [ ] Change `calculateProviderCost` to accept normalized usage and charge output tokens exactly once, using text/reasoning/other splits only when rates differ.
- [ ] Extend `schemas/intelligenceSchema.ts` pricing metadata to support cache-read/cache-write and output text/reasoning/other rates while preserving existing flat pricing fields for UI compatibility.
- [ ] Add provider/model usage capability metadata or validation so missing or inconsistent token splits warn loudly instead of silently producing misleading billing.
- [ ] Update `src/components/DebugAction.tsx` to show cached input and reasoning output token splits in the action debug UI.
- [ ] Add focused regression coverage for xAI-style usage where `output.total = text + reasoning`, verifying reasoning is persisted and not double-charged.
