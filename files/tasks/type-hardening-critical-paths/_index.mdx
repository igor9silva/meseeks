# Type hardening for critical paths

Current code-only baseline (excluding PoCs):
- `any`: **95**
- `@ts-ignore`: **7**
- `@ts-expect-error`: **8**
- non-null assertions (`!`): **29**

Critical-path hotspots include:
- `convex/schedules.private.ts` non-null assertions on schedule fields
- `skills/tools.ts` `@ts-ignore` around tool `execute`
- `src/router.tsx` `(import.meta as any).env`
- `convex/tasks.private.ts` `z.record(z.any())` in action args
- `apps/organizer/src/components/tasks/TaskExplorerPage.tsx` implicit any-heavy callbacks

## Objective
Eliminate unsafe type escapes in core execution/scheduling flows and make those paths strict enough to refactor safely.

## Subtasks
- [ ] Remove non-null assertions from schedule-critical paths:
  - `convex/schedules.private.ts` (`scheduledAt!`, `cronExpression!`)
  - replace with explicit discriminated checks and narrowed branches
- [ ] Remove direct type suppression in runtime tool orchestration:
  - replace `@ts-ignore` in `skills/tools.ts` with a type-safe tool-map construction path
  - keep behavior unchanged while removing suppression
- [ ] Replace unsafe env typing in router bootstrap:
  - remove `(import.meta as any)` in `src/router.tsx`
  - introduce typed env access pattern compatible with existing build setup
- [ ] Replace permissive action arg typing:
  - remove `z.record(z.any())` in `convex/tasks.private.ts`
  - use schema-backed `unknown` + narrowing/validation at usage boundaries
- [ ] Stabilize organizer explorer typing:
  - remove implicit `any` callbacks in `apps/organizer/src/components/tasks/TaskExplorerPage.tsx`
  - fix broad `{}` access patterns (for example `task.title` access on untyped values)
- [ ] Add regression checks for this task scope:
  - grep-based check in CI for `@ts-ignore`/`@ts-expect-error` in touched files
  - targeted `bunx tsgo` invocation for affected workspace(s)
